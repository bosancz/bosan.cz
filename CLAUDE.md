# Project notes

- `web/` is an Angular 22 app (standalone, signals, OnPush) started from `smallhillcz/skeletons` `angular-pwa`, without the service worker. Needs Node ≥ 22.22.3 (`nvm use 24`, `NVM_DIR=/opt/nvm`).
- **Every route is prerendered to static HTML** (`outputMode: "static"`, `app.routes.server.ts`), including `/fotogalerie/:album` for every album; `/fotogalerie/:album/:photo` is client-only (`index.csr.html`). nginx serves `$uri/index.html`, falls back to `index.csr.html` under `/fotogalerie/` and to `/404/index.html` elsewhere. The build needs network access to the API.
- `ApiService.live()` renders build-time data from the prerendered HTML (HTTP transfer cache) and re-fetches once in the browser after hydration, so the program never shows stale data.
- SEO: every page calls `SeoService.set()` (title, description, canonical, OG/Twitter, JSON-LD). `SeoService` hoists the meta tags right after `<title>` — WhatsApp reads only the start of the page and they used to sit behind ~28 kB of inlined CSS. `scripts/og-images.mjs` (run in the Dockerfile after the build) renders `/og/album-<id>.jpg` and `/og/report-<id>.jpg` (title photo + navy panel with logo, name, date; sharp + opentype.js, so no browser) for every prerendered album/report, falling back to `img/og-default.jpg`. `scripts/seo-files.mjs <configuration>` writes `sitemap.xml` and `robots.txt` from `dist/prerendered-routes.json`; only `production` is indexable.
- Breakpoint: `@use "styles/breakpoints" as bp;` — `bp.mobile` is ≤ 860 px. Design tokens are CSS variables in `src/styles.scss`.
- **Redesign work goes to the `redesign` branch** (the repo's default for now): every redesign task is a PR into `redesign`, and after a merge release `redesign` to TEST unless Martin says otherwise.
- Releases: "Release to TEST" (`release-test.yml`, `workflow_dispatch`) builds the Docker image of the chosen branch with `NG_CONFIGURATION=test`.
- No explanatory comments in code. Conventional Commits, description in Czech.
- **Editable texts live in `web/src/content/*.json`** (O nás, Tábor, Kontakty, Aktuálně), typed and exported by `content/content.ts`; templates never hardcode them. Text fields are inline markdown (bold, italic, link): `| inlineMarkdown` for one line, `| paragraphs` + `<p [innerHTML]>` for multi-paragraph text (emulated encapsulation doesn't style `[innerHTML]` children, so paragraphs must be real template elements). Layout derived from data (camp chapter layout = photo count, session id/label from dates), never stored. Exception: the O nás history is not in the CMS — `pages/about/about-history.ts` holds it (forum quotes with nicknames, grouped into eras) for a custom layout. Aktuálně `messages` are hand-written notices for parents shown first in Aktuality; one disappears after its `until` day.
- **Sveltia CMS on `/admin`** (`web/public/admin/config.yml`, version pinned in `index.html`): GitHub backend on the `redesign` branch (switch `backend.branch` to `master` when the redesign ships), `publish_mode: preview` (every save = PR, Publish merges), token sign-in or Sign In with GitHub. A new content field needs a field in `config.yml` too. Uploads go to `web/public/img/<page>` as WebP. No custom preview templates. `web/.prettierignore` keeps Prettier off `src/content/*.json`, since Sveltia writes them (tabs, expanded arrays). Test the config locally with `backend: name: test-repo` + a `cms-seed-url` manifest.
- **GitHub sign-in for the CMS is served by nginx itself** (njs, `nginx/cms-auth.js`, `GET /cms-auth/auth` + `/cms-auth/callback`, same protocol as `sveltia-cms-auth`): state cookie, code → token exchange with `CMS_GITHUB_CLIENT_ID`/`CMS_GITHUB_CLIENT_SECRET` from the container env (declared via `env` in `nginx/nginx.conf`, which also loads the module), token posted only to the popup's own origin. `admin/index.html` sets `base_url` to `location.origin` via `CMS.init()`, so bosan.cz and test.bosan.cz each sign in through themselves; one OAuth app with callback `https://bosan.cz/cms-auth/callback` covers subdomains (`redirect_uri` is sent). `nginx/templates/default.conf.template` gets `resolver` from `NGINX_LOCAL_RESOLVERS` (needed by `ngx.fetch`). njs has no parameter destructuring.
